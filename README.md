# 视频生成工作流

通用的六步视频生成工作流：什么类型的视频都能做，包括短剧、漫剧 / 绘本、口播短视频、产品种草视频，不针对某一种视频写死。

左栏是六步工作流面板，右侧是无限画布，分镜以卡片形式放在画布上，可拖放排版、按剧情顺序连线，画布与左栏双向联动。多项目并存，选题、脚本、分镜、角色和已生成视频各自独立保存。

## 六步流程

1. **选题与设定**：题材 / 主题、视频类型、画幅（竖屏 9:16 或横屏 16:9）、目标时长、目标受众、发布平台、整体基调。
2. **脚本**：按选题生成完整脚本，也可粘贴已有脚本；重新生成不会弄丢已保存的脚本。
3. **分镜**：把脚本拆成一个个分镜，自动排到右侧画布上并按顺序连线。
4. **角色定妆、连续性检查与视频生成**：角色棚 / 角色圣经锁定形象，检查相邻分镜衔接，再生成真视频。
5. **拼接成片**：把已生成的分镜片段拼成可下载的 MP4 成片，页面内可播放预览。
6. **导出与发布**：下载成片，整理发布标题文案；真正发布前须用户确认，不自动发布。

## 关键特性

- **真视频，不冒充**：每镜都是真实生成的视频文件再拼接，不用图片动效冒充。
- **并发生成**：一批最多同时生成 6 条，超过自动拆批；已成功的镜头不重复生成，失败只重试失败的；额度用完会明确提示是额度问题。
- **人物一致性验收（第 4 步，默认宽松）**：每镜生成时带全员定妆锚图（含只在背景出现的人物），提示词写死性别 / 外貌 / 发型 / 服装特征，名单外零人物；收片后抽帧验收，不过自动重生成（最多 2 次）。宽松模式（默认）只拦三类硬伤——主角认错人、关键剧情动作错缺、必需的关键角色全程没出镜，其余细节（衣服文字、徽章、背景多出人、脸模糊等）只记提醒；严格模式保持逐人比对、零容忍。每张分镜卡都可以「人工放行」直接采用当前成片进拼接；额度标记误锁时可一键清除重试（`resetShotQuota`）。
- **连续性检查**：逐对核对相邻分镜，结论分衔接成立 / 小跳跃 / 衔接断裂三档，写回台账、卡片与连线颜色；一键修复全部，修完自动复查。
- **长任务后台化**：点击立即返回、显示进度、断点续跑、防重复点击；卡住的镜头自动重生成（每镜上限 2 次）。
- **声音与字幕**：每镜必须有声音；台词镜头要求口型同步，旁白才用后期画外音；字幕白字加黑色描边，无背景色块。拼接只保留每镜原片自带声音，只烧字幕，绝不二次配音。
- **文本模型可换**：默认走 Muse 推理，也可配置 OpenAI 兼容接口（`/v1/chat/completions`），Key 只存设置、页面只显示掩码；图片和视频永远只用 Muse。

## 技术栈

- TypeScript + React 19 客户端，Bun 运行时
- 服务端 SQLite（Drizzle ORM，迁移在 `drizzle/`）
- 拼接用宿主机 ffmpeg（字幕烧录、尾帧定格 + 叠化）

## 运行方式

本仓库是一个 **Muse 空间（space）**的源码，在 Muse 里打开即用。

本地开发需要 Bun（`package.json` 注明 `bun@1.3.10`）与 ffmpeg：

```bash
bun install
bun run typecheck   # 前后端类型检查
bun run build       # 构建服务端与客户端
```

完整运行依赖 Muse 空间运行时提供的能力（见下），只在本地 `bun run build` 无法跑起整个应用。

## 移植说明（给非 Muse 环境）

以下三处与 Muse 运行时绑定，拿到别处用需要自行替换：

1. **视频生成**（`server/src/actions.ts` 的 `spawnVideoTask`）：经 `ctx.agent.spawnTask` 派 Muse 后台任务调用 Muse 视频生成。出了 Muse 没有这个后端，需要把这一处换成自己的视频模型接口（Runway / Kling / Veo 等），保持 `jobStep` / `saveShotVideo` 的收片回写契约不变。
2. **图片生成**（角色定妆图）：走 `ctx.tool.generate_media`，同样是 Muse 运行时能力，需替换为自己的图片模型接口。
3. **`@hatch/space-sdk`**：`package.json` 里是 `file:` 本地引用，由 Muse 空间运行时提供，不在 npm 上。独立运行需要去掉这层依赖，改成自己的服务端框架与存储。

文本推理与连续性核对默认也走 Muse 推理，但已支持 OpenAI 兼容接口，填自己的 Key 与地址即可。

## 目录结构

```
client/src/      前端：App.tsx、api.ts、样式与入口
server/src/      服务端：actions.ts（全部动作）、schema.ts（表结构）、privileged.ts（ffmpeg 拼接等特权操作）
drizzle/         数据库迁移（含第 4 步硬验门禁的 qa_* 列）
space.json       空间元信息（runtime、入口、slug）
DATA-PLAN.md     架构与数据流说明（含硬验门禁与卡住自愈的设计记录）
AGENTS.md        构建与维护须知
```

## 数据

`app.db`（项目数据）与 `blobs/`（生成的视频文件）不在仓库里，首次运行会自动建库建表，不预置任何示例项目。
